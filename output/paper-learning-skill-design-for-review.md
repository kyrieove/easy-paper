# 论文精读与英文写作学习 Skill：需求与设计讨论稿

本文整理当前已确认的需求、已有样稿和初步设计，供 Claude 独立评议。它是设计讨论稿，尚不是已经实现的 SKILL.md。

## 1. 用户的真实需求

用户正在撰写科研论文，实验和数据分析已有进展，但缺少足够的领域知识与研究经验，难以判断理论预期、理解实验结果，以及组织 Introduction 和 Discussion。用户已经收集了 200 多篇本地 PDF，却难以静下心持续阅读原文。

用户希望最终产物是一个可重复使用的 skill：将每篇论文转化为易读的英文学习材料，让自己读后形成专业知识和判断能力，同时学习学术英语写作。

这里的“用于写论文和思考实验结果”是学习的最终用途，不意味着每篇产物都需要替用户联系其当前研究。用户希望自行思考这些联系。

核心目标可以概括为：

> 制作一个轻量、节省 token 的 skill，将本地论文转化为配有必要原图的易读英文精读材料，帮助用户形成专业知识，并通过一个简短板块学习学术写作。保留证据和来源，不连接用户的文章，不推荐下一篇阅读。

## 2. 已确认的要求

### 2.1 学习与理解

- 降低原论文的阅读门槛和阅读负担。
- 补充理解当前论文所必需的背景知识和概念。
- 讲清研究问题、理论预期、研究设计与论证过程。
- 解释结果如何支持结论，而不只是罗列发现或翻译摘要。
- 保留争议、反例、替代解释以及结论边界。
- 让用户积累可以自行运用的知识，而不是只得到一份看起来完整的分析报告。
- 按论文类型调整讲解方式，不把综述强行套成实验论文。

### 2.2 语言与写作学习

- 正式阅读产物全部使用英文。
- 英文应易读，但保留必要的专业术语和科学准确性。
- 设置一个简短的写作学习板块。
- 可以精选原文表达，解释其写作功能，再给出可迁移的常见句式和适用条件。
- 同时关注句式与论证组织，例如如何提出问题、引入转折、解释结果和限定结论。
- 区分原文引用与原创教学示例，避免把示例当成原论文结论。
- 写作示例围绕当前阅读论文，不替用户的研究拟写 Introduction 或 Discussion。

### 2.3 图文结合

- 必须纳入理解论文所需的原图。
- 图片出现在相关讲解附近，不统一堆到文末。
- 优先选择实验设计、理论模型和关键结果所必需的图。
- 图号、坐标、图例、面板编号及必要图注应可读、可追溯。
- 讲解应告诉读者看哪里、比较什么、图中证据支持什么。
- 必要时可以展示多面板图的相关部分，但保留上下文，不能裁掉影响解释的信息。
- 不要求收录每一张图；不机械增加装饰图。
- 原文没有图时不强行配图，不把生成示意图冒充原图。
- 关键表格也应根据理解需要保留或清晰呈现，不能只关注图而遗漏表中证据。

### 2.4 轻量化与 token 效率

- 节省 token 和轻量化是主要目标，不是附加优化。
- 尽量本地完成提取、格式转换和基础清理。
- 避免重复解析、重复输入全文、工具输出截断后的重读。
- 保存可复用的来源材料和定位信息。
- 模型按需读取正文、图表与参考资料。
- 不用牺牲必要内容覆盖来节省 token，不以只读摘要冒充精读。
- 尚未指定具体 token 上限、输出字数或成本目标。

### 2.5 明确排除

- 不设置“连接到我的文章／研究”板块。
- 不替用户把文献套到其当前结果上。
- 不推荐“下一篇读什么”。单凭当前论文的引用和不完整的用户背景，无法可靠判断最佳阅读顺序。
- 不默认生成正式同行评审报告。
- 不要求全文逐句翻译。
- 不为追求栏目齐全而添加没有学习价值的内容。

理解测验曾出现在早期样稿，但不在当前五部分结构中；目前不作为必要功能。跨论文知识综合也不是当前已经确定的第一版交付要求。

## 3. 当前拟定的阅读产物结构

以下是阅读材料的结构，不是 skill 内部文件布局。标题和正文在正式产物中使用英文。

| 部分 | 内容与作用 |
| --- | --- |
| Before You Read | 简要交代文章研究什么，以及理解它需要的基础背景 |
| Understanding the Paper | 主体部分：连贯讲清概念、论证、方法与发现；必要原图在对应位置出现 |
| What the Evidence Supports | 梳理关键结论、依据、替代解释与结论边界，避免与正文大量重复 |
| Learning to Write | 简短的英文写作教学：原文表达、写作作用、可迁移句式与适用条件 |
| Key Takeaways | 简短收束值得掌握的知识和重要区别，便于回顾 |

主体根据论文性质组织。例如：

- 实验论文：研究问题、理论预期、设计逻辑、观察结果、解释过程。
- 综述或观点文章：核心问题、概念框架、不同证据与立场、分歧和综合判断。

背景知识应在需要时补充，不应全部堆到开头。正文以连贯讲解为主，表格用于确实需要比较的内容。需要避免把材料变成术语密集、栏目众多的报告。

## 4. 证据与来源要求

目前认可的原则：

1. 关键论断能够回到原文页码、章节或图表位置。
2. 明确区分原文结果、作者解释、补充背景与分析者推测。
3. 引用综述中的原始研究时，说明是否实际读过原始论文，不能把二手概述冒充独立核查。
4. 材料缺失或解析不可靠时说明无法判断，不编造页码、图表或结果。
5. 区分作者明确承认的局限与分析者提出的问题。
6. 来源定位正确不代表解释一定正确；仍需核对关键论断是否确实得到证据支持。

尚待设计的问题包括：这些标记如何做到清晰而不打断阅读，证据检查应放在后台还是以附录形式保存。

- 该 skill 明确排除学术英语收集，而用户需要一个写作学习板块。
- 不需要每篇都生成研究想法，也不需要将每个检查项变成可见栏目。

当前判断是借鉴其证据纪律，而不照搬全部输出形式。“集百家之长”应体现为围绕目标选择有效方法，而非堆叠更多技能或栏目。

## 6. 初步的轻量处理流程

下面是拟议方案，尚未实现或测试。

### 6.1 一次性本地预处理

- 检查 PDF 是原生文本、扫描件还是混合类型。
- 提取正文并转换为结构清晰的 Markdown。
- 保留 PDF 页码与章节、文本块的对应关系。
- 去除重复页眉页脚，修复排版断行；保留原始提取结果以供核对。
- 将正文、参考文献和补充内容分开保存。
- 保存必要图片、图注和图表定位，避免后续重复提取。

### 6.2 模型读取与讲解

- 覆盖完整的相关正文，分章节或合理段落读取。
- 读取必要原图和表格；仅在需要视觉核对或解析异常时读取整页图像。
- 对关键论断建立简洁的证据对应记录。
- 在需要补基础时进行针对性补充，不默认扩展成新的文献综述。
- 输出英文图文讲解与简短写作板块。

### 6.3 复用与修改

- 同一 PDF 后续运行优先复用已有提取结果。
- 修改写作板块不应触发全文重新解析和读取。
- 缓存需要能识别原 PDF 已变化的情况；具体实现尚未决定。
- 暂不引入大型数据库、向量检索或多 agent 架构；这些都不是当前已确认需求。

重要区别：本地程序提取文字通常不需要模型 token。主要输入消耗来自将文字和图像传给模型。PDF 转 MD 不会自动让等量正文大幅减少 token；主要收益来自清理噪声、结构化读取、减少重复和复用中间结果。详细输出本身也有 token 成本，仍需平衡教学深度和篇幅。

## 7. PDF Inspector：候选工具，尚未选定

用户提到 PDF Inspector。当前查到的候选是 [firecrawl/pdf-inspector](https://github.com/firecrawl/pdf-inspector)，但用户尚未确认是否指这个项目。

查阅官方说明后了解到，它提供 PDF 分类、Markdown 转换、指定页面提取、页码标记、紧凑输出，以及按需 OCR 的相关接口。尚未安装，也没有用用户的论文进行实测。

当前不能宣称它是最佳选择，不能宣称已经节省某个比例的 token，也不能假定它能完整提取论文图。

需要验证：

- 双栏正文的阅读顺序。
- 标题、图注、表格、公式与特殊符号的保真度。
- 页码定位的可靠性。
- 原图或矢量图的提取是否需要其他工具补充。
- 扫描页和混合 PDF 的处理方式与依赖负担。
- 在用户 Windows 环境中的可用性。
- 相比简单文本提取，是否减少修复、重复读取和总 token 消耗。

工具运行速度、文本准确性与模型 token 消耗是不同指标，不能相互替代。
